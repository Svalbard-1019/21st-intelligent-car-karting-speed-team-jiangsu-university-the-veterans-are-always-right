# kart_508 工程理解指南

这份文档的目标不是把每一行代码都解释一遍，而是帮你建立一张“整车程序地图”。先知道数据从哪里来、经过哪些模块、最后怎么变成电机动作，再去看具体函数会轻松很多。

## 1. 推荐阅读顺序

建议按下面顺序读，不要一上来就从 `libraries` 或所有 `.c/.h` 文件开始翻。

1. `user/cpu0_main.c`
   - 看启动流程、主循环、不同模式如何分流。
   - 重点函数：`core0_main()`、`Guandao_Rear_Motor_Update()`、`Serial_Debug_Update()`。

2. `code/display.c`
   - 看屏幕菜单怎么选择模式。
   - 重点函数：`Menu_Mode_Choice()`、`Menu_Recode_Points()`、`Menu_Parameter()`。

3. `user/isr.c`
   - 看哪些东西在中断里周期执行。
   - 重点中断：`cc61_pit_ch0_isr()`、`cc61_pit_ch1_isr()`。

4. `code/guandao.c` 和 `code/guandao.h`
   - 科目一核心：记录路线、平滑路线、纯追踪、停车点、倒车。
   - 重点函数：`guandao_recode()`、`update_state()`、`recode_waypoint()`、`portion_1()`、`pursuit_contral_mode()`。

5. `code/rear_motor/rear_motor.c` 和 `code/rear_motor/rear_motor.h`
   - 后轮 m/s 闭环控制。
   - 重点函数：`rear_motor_encoder_update_10ms()`、`rear_motor_pid_update_100ms()`。

6. `code/angle_control.c` 和 `code/control.c`
   - 前轮转向闭环和旧控制接口。
   - 重点函数：`Steer_Moter_Contral()`、`angle_control_update()`。

7. `code/flash.c`
   - 路线点、停车点、PID 参数如何掉电保存。
   - 重点函数：`Flash_Main_Read()`、`Flash_Store_Mode()`、`Flash_Read_INSpoints()`。

## 2. 工程启动主链路

主入口在 `user/cpu0_main.c` 的 `core0_main()`。

```text
clock_init()
debug_init()
Init_All()
rear_motor_init()
uart_receiver_init()
pit_ms_init(CCU61_CH1, 1)
pit_ms_init(CCU61_CH0, 1)
Flash_Main_Read()
Menu_Contral()
Flash_Write_pid()
Main_Key_Flag = 1
while(TRUE)
```

进入 `while(TRUE)` 后，主循环每次都会先调用：

```text
sbus_rc_control()
```

然后根据 `main_mode` 分流：

```text
Guandao_Recode_Mode  -> guandao_recode(&INS)
Guandao_portion_1    -> portion_1()
Guandao_Voice        -> portion2_points_trace()
Guandao_portion_3    -> guandao_trace(&INS)
Rack_Test_Mode       -> Rack_Test_Run()
```

每轮主循环末尾还会调用：

```text
Guandao_Rear_Motor_Update()
Serial_Debug_Update()
```

所以你看主循环时，要记住一句话：**主循环负责模式逻辑和后轮目标速度，中断负责周期采样和转向输出。**

## 3. 两个核心状态变量

工程里有两个非常重要的模式变量：

```c
main_mode
conrtol_mode
```

`main_mode` 决定主循环正在做什么：

```text
Mode_IDLE
Guandao_Recode_Mode
Guandao_portion_1
Guandao_Voice
Guandao_portion_3
Rack_Test_Mode
```

`conrtol_mode` 决定中断和电机控制走哪套输出：

```text
IDLE
YAOKONG
GUANDAO
RACK_TEST
DAOCHE
```

举例：

- 记录模式：`main_mode = Guandao_Recode_Mode`，`conrtol_mode = YAOKONG`
- 科目一自动驾驶：`main_mode = Guandao_portion_1`，`conrtol_mode = GUANDAO`
- 倒车停车：`conrtol_mode = DAOCHE`
- RackTest：`main_mode = Rack_Test_Mode`，`conrtol_mode = RACK_TEST`

调试时如果屏幕显示的模式和电机行为不一致，优先怀疑这两个变量是否匹配。

## 4. 科目一记录模式

入口：

```text
Menu_Recode_Points()
-> main_mode = Guandao_Recode_Mode
-> guandao_recode(&INS)
```

记录模式主要流程：

```text
guandao_recode()
-> update_state()
-> recode_waypoint()
-> Flash_Store_Mode()
```

`update_state()` 做的事：

```text
后轮编码器增量 + Yaw_1
-> 计算车辆当前 x/y/theta
```

`recode_waypoint()` 做的事：

```text
如果移动距离 >= recode_threshold
-> 自动记录一个路线点
```

当前 `recode_threshold = 0.2f`，单位是米。意思是推车每移动约 0.2 m 自动记一个点。

记录模式按键/遥控：

```text
普通路线点：不用按，推车自动记录
KEY1 短按：记录停车点
KEY1 长按：保存路线到 Flash
遥控 CH4：记录停车点
遥控 CH3 短按：记录 GPS 辅助点
遥控 CH3 长按：保存路线到 Flash
```

注意：停车点是惯导路线点，不是 GPS 点。GPS 辅助点目前只是辅助记录/校验，不参与停车和倒车判断。

## 5. 科目一自动驾驶模式

入口：

```text
Menu_Mode_Choice()
-> Guandao_portion_1
-> portion_1_reset()
-> main loop 调用 portion_1()
```

自动驾驶主流程：

```text
portion_1()
-> update_state()
-> guandao_build_smooth_plan()
-> pursuit_contral_mode()
-> 输出 out_v_l / out_v_r / out_servo
-> Guandao_Rear_Motor_Update()
-> rear_motor_set_target_mps()
-> rear_motor_pid_update_100ms()
```

`portion_1()` 是科目一的总控制函数。它负责：

- 更新当前位置
- 第一次进入时生成平滑路线
- 正向追踪路线
- 到停车点后进入倒车状态机
- 倒车完成后停车

`pursuit_contral_mode()` 是纯追踪控制函数。它负责：

- 根据当前点 `Idx` 找目标点
- 计算 `D` 距离和 `A` 角度误差
- 计算转向目标 `out_servo`
- 计算左右后轮旧速度单位 `out_v_l/out_v_r`

然后 `Guandao_Rear_Motor_Update()` 会把旧速度单位换成 m/s：

```text
target_mps = (out_v_l + out_v_r) * 0.5f * GUANDAO_SPEED_TO_MPS
```

当前 `GUANDAO_SPEED_TO_MPS = 0.1f`，所以旧速度单位 5 对应约 0.5 m/s，旧速度单位 10 对应约 1.0 m/s。

## 6. 停车点和倒车状态机

停车点来源：

```text
记录模式短按 KEY1 或遥控 CH4
-> daoche_point_length = 当前路线点索引
```

自动驾驶时，如果 `daoche_point_length` 有效，`portion_1()` 会先只追到停车点附近。

倒车状态机在 `portion_1()` 内部，目前有 4 个阶段：

```text
0：正常正向追踪
1：到停车点，停车等待 300ms
2：倒车中
3：倒车完成，最终停车
```

屏幕 `Reason` 对应：

```text
6：到停车点，等待倒车
7：正在倒车
8：倒车完成并停车
```

倒车结束条件：

```text
倒车距离 >= 0.55m 且倒车时间 >= 1.8s
或倒车时间 >= 3.5s
```

这样做是为了防止惯导距离瞬间跳变，导致只倒几厘米就误判完成。

自动驾驶阶段不需要再次按停车点。停车点只在记录模式按一次。

## 7. 后轮速度控制

后轮模块在：

```text
code/rear_motor/rear_motor.c
code/rear_motor/rear_motor.h
```

调用链：

```text
CCU61_CH0 中断
-> rear_motor_encoder_update_10ms()

主循环
-> Guandao_Rear_Motor_Update()
-> rear_motor_set_target_mps()
-> rear_motor_pid_update_100ms()
-> rear_motor_set_pwm()
```

关键参数在 `rear_motor.h`：

```text
REAR_WHEEL_DIAMETER_M
REAR_GEAR_RATIO
REAR_ENCODER_PPR
REAR_KP / REAR_KI / REAR_KD
REAR_FF_GAIN
REAR_PWM_HARD_LIMIT
REAR_PWM_RATE_LIMIT
```

调后轮时重点看：

```text
TgtAct
PWM
Enc10
Enc100
```

如果 `TgtAct` 目标有值但 `PWM=0`，优先查控制模式或 stop 条件。

如果 `PWM` 有值但 `Act` 不动，优先查电机驱动、编码器接线、编码器计数方向。

## 8. 前轮转向控制

转向相关主要在：

```text
code/control.c
code/angle_control.c
code/angle_control.h
```

自动驾驶输出链路：

```text
pursuit_contral_mode()
-> out_servo
-> CCU61_CH0 中断
-> Steer_Moter_Contral(out_servo)
-> angle_control_set_target()
-> angle_control_update()
-> angle_motor_set_pwm()
```

当前科目一上层转向命令已按机械极限限制在约 `±35°`。

调转向时重点区分两个角：

```text
out_servo：科目一希望前轮转多少
angle_ctrl.current_angle：转向电机编码器反馈的真实角度
```

如果 `out_servo` 有变化但轮子不动，查转向电机、驱动、编码器闭环。

如果轮子能动但方向相反，查 `out_servo` 符号或 `Steer_Moter_Contral()` 内部方向。

## 9. 中断里做了什么

主要看 `user/isr.c`。

`CCU61_CH0`：

```text
每约 10ms：
-> 根据 conrtol_mode 输出转向
-> rear_motor_encoder_update_10ms()

每约 100ms：
-> GPS 数据解析
```

`CCU61_CH1`：

```text
按键扫描
IMU963RA 陀螺仪读取
姿态解算 IMU_GetValues()
```

理解中断时要记住：不要在主循环里重复抢同一个编码器计数。当前后轮速度模块是在中断里采样，主循环里做 PID。

## 10. Flash 保存了什么

Flash 相关在：

```text
code/flash.c
code/flash.h
```

上电读取：

```text
Flash_Main_Read()
-> Flash_Read_INSpoints()
```

记录模式保存：

```text
Flash_Store_Mode(route_setting_choice)
```

保存内容包括：

- 路线点 `INS.recode_map[]`
- 路线长度 `INS.length_index`
- 停车点 `daoche_point_length`
- GPS 辅助点
- 部分控制参数

重新烧录通常不会清掉 Flash 路线点，除非程序主动擦写对应 Flash 页，或者你更换了保存结构/地址。

## 11. 屏幕和串口数据怎么看

自动驾驶屏幕重点：

```text
Idx：当前追踪点
Len：路线长度
D：到目标点距离，单位 m
A：目标方向和车头方向的夹角，单位 deg
Reason：当前追踪/停车原因
VlVr：左右轮旧速度单位
TgtAct：后轮目标/实际速度，单位 m/s
PWM：后轮 PWM
Yaw：IMU 航向角
XY：惯导坐标
```

常见 `Reason`：

```text
0：正常追踪
2：距离到点，切到下一个点
4：到终点或最终停车
5：最近点搜索跳点
6：到停车点，等待倒车
7：正在倒车
8：倒车完成并停车
```

串口日志：

```text
REC：记录模式数据
AUTO：自动驾驶数据
```

如果自动驾驶跑偏，优先看：

```text
Idx 是否正常增加
D 是否长期很大
A 是否经常大于 60°
Yaw 是否跳变
TgtAct/PWM 是否突然变大
XY 是否连续变化
```

## 12. 遇到问题时怎么定位

### 记录模式 Len 不变

看：

```text
Enc 是否变化
X/Y 是否变化
recode_threshold 是否过大
```

`Enc` 不变：查后轮编码器接线或编码器初始化。

`Enc` 变但 `X/Y` 不变：查 `update_state()` 或 `ONE_TICK_DISTANCE`。

`X/Y` 变但 `Len` 不变：查 `recode_threshold`。

### 自动驾驶开一下就停

看：

```text
Idx 是否跳到 Len
Reason 是否变成 4/8
TgtAct 是否变 0
daoche_point_length 是否误设
```

### 方向盘乱打

看：

```text
A 是否很大
Yaw 是否跳变
Idx 是否跳点
out_servo 是否超过机械极限
```

当前机械极限约 `±35°`，所以不要让上层长期输出更大的目标。

### 后轮目标有但车不动

看：

```text
TgtAct
PWM
Enc10
Enc100
```

`PWM=0`：查模式和 stop 条件。

`PWM 有值，Enc=0`：查驱动、电机、电源、编码器。

### 倒车只倒一点

看：

```text
Reason 是否 7
TgtAct 是否为负
Act 是否为负
fd100 或 guandao_debug_dist_final 是否跳变
```

现在倒车加了最短时间保护，正常不会只倒几厘米就结束。

## 13. 读代码时的好习惯

每读一个函数，都问 5 个问题：

1. 谁调用它？
2. 它依赖哪些全局变量？
3. 它修改哪些全局变量？
4. 它有没有硬件输入/输出？
5. 它属于主循环还是中断？

对嵌入式车控代码尤其重要，因为很多 bug 不是函数本身错，而是“主循环和中断同时改同一个状态”。
